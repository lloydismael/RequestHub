# Unreleased: Unified SQR Tracker

Feature changes implemented; final acceptance and conditional release verification remain open. Not published in Notifications. No release revision or visual approval has been invented.

## Data and compatibility

- Restored runtime declarations for the three Delivery assessments, transition metadata, and singleton tracker settings to match existing migrations. Historical migrations 0061 and 0062 are unchanged; the additive migration only adds frozen legacy completion provenance.
- Schedule Performance supports On Track, At Risk, and Delayed; Budget/Effort supports Within Budget, At Risk, and Over Budget; Quality supports Met, At Risk, and Unmet. Shared normalization distinguishes missing/partial assessments from green, amber, and red results. Completion and On Hold do not manufacture ratings.
- Conservative transition fills blank Schedule only from legacy On Track/At Risk. Off Track and terminal legacy Health values are not guessed as new assessments; existing recorded values, Budget/Effort, Quality, dates, lifecycle, and metadata are preserved.
- Existing Signed-only completion is frozen without inventing Finish dates. New unmarked Signed-only records stay open; cancellation remains authoritative. Reversing the data migration intentionally preserves provenance and later assessments.
- Added a read-only transition preview for health/backfill counts, terminal conflicts, warranty differences by applicable scope, invalid assessments, and manual/computed Maintenance differences. Apply migrations to a real database only after its deployed migration history has been reconciled and the preview reviewed; never use blind migration faking.

## Delivery editors and Maintenance

- Active Classic Delivery, Tracker, and configured forms now use Finish and the three independent performance assessments. Target Finish, Completion Signed, legacy Health, stored warranty, and Effective Maintenance Start are archival-only, not active controls. Classic editable/read-only rows share the same 13-column Delivery contract and safe labeled green/amber/red badges; missing and invalid ratings remain visibly unassessed.
- Completion Warranty End uses Finish +30 calendar days within the existing independent warranty scope rules. Maintenance Start/End are manual dates; Finish and warranty never populate or overwrite them. Ineligible scopes retain stored manual dates but expose no active computed Maintenance dates; zero support amount still qualifies where applicable.
- Forms, inline edits, imports, and undo merge saved date counterparts. End-only and reversed Maintenance dates are rejected when the tuple changes; unchanged invalid historical tuples do not block unrelated updates. Same-day and Start-only entries are valid, without a warranty-overlap restriction.
- Inline save/undo responses include raw ISO Maintenance dates and refresh eligibility/warranty without destroying editable markup. Direct Delivery saves record atomic permanent history and 24-hour undo snapshots only when values actually change.
- Published and pinned historical form layouts retain the canonical current Delivery contract, labels, and unrestricted canonical assessment choices while preserving custom-field/version behavior. Headerless historical import positions stay frozen; canonical headers, including explicit blanks, win over aliases. Current exports retain a clearly labeled Legacy Health column without treating it as a rating or completion source.
- Saved invalid Maintenance pairs display review notices in Delivery/Tracker forms (including published/pinned layouts), editable/read-only Classic rows, and unified Tracker attention even while On Hold. Ineligible stored dates display an inactive notice without erasing archival values. Inline edits and undo refresh these notices using text-only DOM updates while preserving active date editors.

## Shared Tracker filters

- A **Filters** funnel opens the unified Tracker's existing filter toolbar in place. It starts collapsed, works by pointer or keyboard, and keeps applied filters when closed. Pipeline shortcuts and search stay visible. Chromium regressions cover applying, reopening, and clearing filters on phone and desktop widths.
- Filters combine multiple choices with OR inside each dimension and AND across dimensions, all-word search, My Assigned, Attention, Price, and inclusive date ranges. Existing Group, Linked Request, Billing, assignment, lifecycle, scope, and all three performance dimensions remain available. Blank assignments and assessments are explicit; unavailable selected IDs remain visible until cleared.
- Tracker fetches the complete authorized pool before local filtering and presentation slicing. Pipeline totals and facets include matching rows beyond the displayed page; each facet excludes only its own dimension. Effective PM labels include the reviewer fallback. Engineer facet options remain limited to their authorized records without exposing additional editing directories.
- Following the confirmed Assigned SSE decision, Engineer/On Hold **My Assigned** matches only explicit saved SSE inside the existing owner-scoped authorized pool. Blank SSE stays Unassigned without a form-owner fallback. The endpoint supplies Engineer-role metadata; a shared predicate keeps List/Table rows, pagination, self-excluding facets, pipeline totals and reassignment notices consistent. Engineer viewers now receive the My Assigned pipeline shortcut. PM/reviewer and PPT Mine matching remain reviewer-based; SSE assignment does not grant read/edit permissions. Unified shared-core/controller cache revisions are now 3/12 (the latest controller revision also synchronizes focused editors during full-snapshot refresh), and README usage explains the distinction.
- Native checkbox disclosures apply drafts atomically, show counts/chips, support option search, Clear and Escape, and retain keyboard focus. Same-filter record refresh preserves open drafts, option search and focus while updating facets/counts; changed external filters replace drafts even when the consumer mutates its original state.
- Session preferences store filters only, never records or permissions. URL filters override saved filters; canonical keys win aliases, legacy Mine/Health are migrated conservatively, and malformed or retired values show a notice. Assessment choices are validated per indicator. Browser storage failure is nonfatal and visible.
- Excel export is explicitly **All records**: it exports all authorized records, independent of screen filters. Shared client filtering does not change server-side authorization or opt-in legacy endpoint pagination.
