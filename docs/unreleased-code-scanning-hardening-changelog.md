# Unreleased: Code-scanning hardening

Status: local validation only. No release version, release date, integrated change revision, or publication is assigned here.

## Changes

- **Sign-in and profile:** The application and Django admin use the same PostgreSQL-backed login quotas before password checks: 30 attempts per client source, five per account and source, and five per existing account across sources in a 15-minute window. Unknown accounts use the source limit; generic feedback and dummy verification avoid disclosing account state. Success clears only completed failures for that account and source; denied attempts do not extend a window, and a quota-storage failure does not allow unchecked authentication. Existing aliases, staff checks, redirects, and proxy resolution are preserved. Accounts flagged for a password change must set a different password before accessing protected pages, including admin. Only the Request Hub Admin role can change their own department.
- **Configuration and migration:** `request_hub/settings.py` uses the custom Django admin app config to select the shared login form without replacing registered models or admin URLs. Apply additive `accounts` migration `0030_loginthrottlebucket` before enabling the sign-in changes; it creates keyed quota rows with indexed expiry and bounded cleanup. No new environment variables, dependencies, or SQR/request schema changes. No live migration was performed. Keep `TRUSTED_PROXY_CIDRS` limited to controlled peers; plan to monitor shared-source and account quota denials in a controlled rollout.
- **SQR approval and tracker:** Admin or the assigned PM-ESG reviewer controls review, protected quote, proposal, and revenue actions. Approved quote fields stay read-only in Classic, the unified tracker, and the submission editor until a reviewer explicitly selects **For Revision**. The same policy governs Save, Undo, and History Restore; reopening clears approval metadata, and reverting a later edit cannot silently reopen a quote or attach incompatible approval history. Existing access to allowed remarks, applicable configured answers, approvals and related email choices, valid Undo, and independently authorized Delivery work is retained. Classic PM and SSE names remain literal after Save and Undo; unassigned cells keep the en dash. The unified tracker asset version was bumped for the changed controls.
- **Request management and recovery:** Removal by confirmation or the scoped DELETE handler is idempotent and preserves the record, status history, and activity for single or bulk Admin recovery. The confirmation explains recovery. Collaborative activity edits share the same request/role check when opening and submitting the editor. New engineer entries credit the actor (including backup engineers); existing authors and authorized admin attribution are preserved. Eligible engineers see the stored account and recorded request date as read-only; the separate Deployment scheduling controls remain editable. Configured answers use saved read-only values, and the manager form displays form-wide validation errors.
- **Tests and maintenance:** Added policy coverage for login quotas, concurrency, password and department rules, reviewer permissions and approval transitions, Undo/Restore and assignment labels after Save and Undo, request removal/recovery, collaborative activity, and configured forms. Mobile and seasonal tests now share standard-library script extraction/omission for trusted local fixtures only; it is not an application sanitizer. The mobile fixture retains inert inline chart JSON only when it opts into local scripts. The PPT keyboard check explicitly enables Classic just for that fixture. Existing CSV/XLSX literal text and numeric-cell safeguards were rechecked; export code was not changed. README documents the rules, rollout order, and verification limits.
